# FormPilot 代码走查：能干什么、缺什么、改了什么

2026-09-06 读了 [FormPilot](https://github.com/rockbenben/form-pilot) 全部 11736 行源码后的结论。
装机步骤在 [formpilot-setup.md](formpilot-setup.md)，这份讲**它到底行不行、我们动了哪里**。

---

## 一、它本来是什么水平

比 README 讲的更实在，也有几个 README 没说的限制。

### 只有一个站点适配器

`lib/engine/adapters/` 底下只有 `moka.ts`。README 列的 Workday、Greenhouse、BOSS、北森、拉勾、智联、飞书
**没有专门适配器**，全靠通用启发式引擎。

这不算缺点——启发式那部分做得很扎实：

- 45 个字段的正则表，注释里明确写了是**对着真实页面验的**
  （猎聘的 `selfAssess` textarea 没有 label、智联把生日叫「出生年月」…）
- 域名白名单已经废弃，改成用「简历字段探针」判断这页是不是申请表，所以**任何站点都可能生效**
- 能对付中文站爱用的自定义控件（点可见按钮而不是改隐藏 input）
- 三层记忆：页面记忆（按 URL）、跨站记忆（按字段 signature）、草稿
- 长文本只写一次——猎聘一个项目给三个 textarea，全填同一段会很难看
- 敏感字段默认跳过（身份证、验证码、密码、银行卡）
- **431 个单测**，代码质量高于一般开源扩展

### 三个对我们致命的问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | **所有含「是否」的字段被无条件跳过** | 你发的基恩士网申里 `是否同时投递校园大使`、`工作地点是否服从公司调配`、`是否有销售相关实习经历`、`是否为在职员工三代以内血亲` —— **一个都填不了** |
| 2 | `custom` 字段没接进填表引擎 | 「毕业届别」「三方协议」「紧急联系人关系」这些校招必问项，在 Resume 结构里没位置，只能挂 custom，但 custom 永远取不到值 |
| 3 | 记忆层要求标签**几乎一模一样** | signature 是标签文本的哈希。「是否有销售相关实习经历?」和「有无销售实习经历」哈希不同，填过一次也复用不上 |

问题 1 的根源能理解：在**社招**平台上，「是否」几乎都是隐私开关（是否公开手机号、是否对当前公司保密），
跳过是对的。但**校招**表单里「是否」恰恰是正文问题。上游是照着社招做的，没考虑校招。

## 二、我们改了什么

都在 `sources/form-pilot/`，MIT 许可，改动带中文注释标了「本地新增/本地改动」。
**458 个测试全过**（原 431 + 我加的 27），TypeScript 类型检查干净。

### 1. 放开「是否」，但不放开「有无」

`lib/engine/heuristic/engine.ts`

```
原来：/…|是否|有无|…/                       ← 一律跳过
现在：/…|是否.*(公开|保密|隐藏|显示|接收|订阅|通知|同意)|有无|…/
```

只有「是否」和隐私、可见性词一起出现时才跳过。

**`有无` 保持原样。** 我一开始两个都放开了，结果撞了他们的智联真实页面回归测试：
「学位证书： 有无」是个纯 yes/no 开关，放开会被 `education.degree` 的 `/学位/` 吃掉填错。
校招表单问的是「是否…」，不用「有无」，所以只放宽前者就够。

### 2. `custom.<key>` 接进填表引擎

`lib/engine/orchestrator.ts` 加了解析分支，按 key 到 `resume.custom` 数组里取值（比较时忽略空白）。

`lib/engine/heuristic/patterns.ts` 加了 15 个校招 / 留学生字段：

毕业届别、毕业时间、应届生身份、三方协议、生源地、期望工作城市、是否服从调剂、
紧急联系人 / 关系 / 电话、婚姻状况、学历认证状态、回国时间、海外院校、是否需要签证担保

配套加了三个守卫，都是被测试逼出来的真 bug：

| 抢字段的 | 被抢的 | 加的守卫 |
|---|---|---|
| `basic.location` 的 `/城市/` | 期望工作城市 | `(?<!期望工作\|意向工作\|期望\|意向\|志愿)城市` |
| `education.degree` 的 `/学历/` | 学历认证状态 | `学历(?!认证\|学位认证)` |
| `skills.certificates` 的 `/认证/` | 学历认证状态 | `(?<!学历\|学位\|留服\|教育部)认证(?!状态\|进度)` |

这三个都是「排在前面的宽泛规则平分时赢了」造成的，上游对 `education.major`、`work.title`
也用同样的守卫写法，所以是顺着它的风格改的。

### 3. 答案库（新增的第 5 层）

`lib/engine/answer-bank.ts` + `answer-bank.data.ts`

一条记录挂**多个问法**，命中任意一个就填：

```ts
{
  id: 'has-sales-intern',
  phrasings: ['是否有销售相关实习经历', '有无销售实习经历', '是否具备销售实习经验'],
  answer: '是',
  kinds: ['radio'],
}
```

设计取舍（按你说的「宁愿重复也要让他知道」）：

- **问法随便加，冗余没关系。** 命中最长的那个（最长通常最具体，最不容易配错）
- **「是」和「否」拆成两条**比塞一条好维护
- 匹配只做「包含」，**不做编辑距离** —— 校招标签普遍很长，模糊匹配容易乱配，宁可漏也别填错
- 跑在**最后一层**：简历、页面记忆、跨站记忆都没管住的字段才轮到它，
  所以不会抢走前面已经填对的东西（有测试盯着）
- `answer` 留空 = 只记问法不填，用来先把问题攒下来

顺手修了个体验问题：启发式没认出字段时 `label` 会退化成 `name`/`id`（比如 `q1`），
popup 里根本看不懂填了什么。答案库既然是靠可见标签命中的，就把标签一起修正回去。

### 4. 从 HTML 抽问题的脚本

`scripts/extract_questions.py` —— 你说的「能不能从 HTML 里解析出它的问题」。

```bash
# 网申页 Ctrl+S 存成 HTML，然后
python scripts/extract_questions.py 那个页面.html --skip-known
```

直接打印成答案库条目的格式，填上答案粘进 `answer-bank.data.ts` 就行。

`--skip-known` 会滤掉简历里已有的字段（姓名、手机、学校…），只留需要你自己答的。
过滤只对**短标签**生效——按子串一律过滤会误伤「工作地点是否服从公司调配」（含"公司"）
和「校招面试站点（请选择您大学所在城市）」（含"所在城市"），这两个都是要你答的问题。

页面是 JS 动态渲染时，另存的 HTML 里可能没有表单，脚本会明说抽到 0 条，不会假装成功。
那种情况用 F12 → Elements → 右键 `<html>` → Copy outerHTML。

### 5. 端到端验证：拿真表跑一遍

光有单测不够——`tests/fixtures/campus-keyence.html` 按你发的基恩士网申**照结构复刻**了一份
（31 个字段，不含任何真实个人信息），`tests/lib/engine/e2e-campus.test.ts` 跑完整流程逐字段审计。

第一次跑出 **14/31**，暴露出四个问题，全修了：

| 问题 | 根因 | 修法 |
|---|---|---|
| 「毕业日期」没填 | `education.endDate` 和 `custom.毕业时间` 都只认「毕业**时间**」，和「毕业**日期**」不共享子串 | 补问法 |
| 「最高毕业学历专业类别」没填 | 先被 `education.major` 的 `/专业/` 抢走（把"计算机科学与技术"填进只有工学/理学的下拉框），加了守卫后又被 `education.degree` 的 `/学历/` 抢走 | 两处都加负向断言 + 新增 `custom.专业类别` |
| **所有是非题选错答案** | 见下 | 见下 |
| 「三代以内血亲」命中不了 | 各家把公司名插进句子中间（「目前**基恩士**在职员工的三代以内」） | 答案库补短核心词「三代以内的血亲」「血亲」 |

**是非题选错答案是个上游真 bug，影响面很大。**
`fillRadio` 匹配不到选项时会退到「父容器的全部文字」，而 `<fieldset>` 的文字是
`工作地点是否服从公司调配 是 否` —— 同时含「是」和「否」，`includes` 必然命中第一个 radio。
**填「否」会选中「是」**，而且题干里只要有「是否」两个字就够触发。
修法：这个容器只包着一个 radio 时才认它的文字。

另外我自己的实现也有个坑：radio 上 `extractSignals` 拿到的是**选项文字**（"是"/"否"）
而不是题干，导致答案库拿「是」去反向匹配任意含「是」的问法——碰巧能过，但等于乱配。
改用上游的 `findLabelText`（它对 radio/checkbox 会优先找组标题），并要求反向匹配时标签本身够长。

**最终 16/31。** 剩下 15 个全是答案库里 `answer` 留空的条目——
有个专门的用例证明**填上答案后 radio / 下拉 / 长文本都能写进去**，链路本身是通的。

想看逐字段结果：

```bash
cd sources/form-pilot
npx vitest run tests/lib/engine/e2e-campus.test.ts --reporter=verbose --disable-console-intercept
```

### 一个已知的结构性限制

引擎按「置信度最高」选字段，平分时**表里排在前面的赢**。所以长标签
（「最高毕业学历专业类别」同时含"学历""专业""类别"）总是被靠前的宽泛规则抢走，
只能一条条加负向断言。更彻底的做法是改成「命中最长的规则优先」，
但那是动上游的核心排序逻辑，风险比收益大，暂时没动。

## 三、怎么用

改完 `answer-bank.data.ts` 要重新构建：

```bash
cd sources/form-pilot && npx wxt build
```

然后 `chrome://extensions` 点扩展上的刷新。构建产物在 `sources/form-pilot/.output/chrome-mv3`。

跑测试：

```bash
cd sources/form-pilot && npx vitest run
```

## 四、还没做的

### 投完自动记进表格（你要的第 ① 条）

**没做。** 需要在扩展里挂一个「提交」检测，再把记录传回工作台。难点：

- 「点了提交」和「真的投成功了」不是一回事 —— 很多站提交后跳转、弹层或静默失败
- 扩展的 storage 和工作台的 localStorage 是两个源，跨不过去，得走导出/导入文件

**能做的折中**：扩展记录「在某域名的某页面填了表」，导出成 JSON；
工作台按 `apply_url` 的域名匹配到岗位行，问你确认后再标成已投递。
**不自动判定成功**——按 AGENTS.md 第 8 条，最后一下得你自己按。

记在 `GOALS.md` 的 G12。

### 其它

- **没在真实浏览器里点过。** 上面的 16/31 来自对真实表单结构的复刻 fixture，
  跑的是真引擎；但真实页面上还有动态渲染、自定义控件库、iframe 这些变量，
  得你装上扩展拿 2–3 家实际试一次
- 答案库现在编译进扩展，改了要重新构建。做成 Dashboard 里可编辑要写 React UI，暂时没做
- 只有 Moka 一个站点适配器。北森、智联这些如果实测发现启发式不够用，可以照 `moka.ts` 再写
